## 2026-06-09 view 分支 I 组 阶段1:useRequest hook + Login demo 迁移

**目的**:落地 F 组设计稿《视图处理方式设计.md》阶段 1 —— 引入 `useRequest` 自定义 hook,把 Login 作为首个 demo 改写,验证抽象可用。后续 Register/mainpage/indexview 留给阶段 2 批量迁移。

**改动范围**:3 个文件(其中 1 个新建)

| # | 项 | 文件 | 说明 |
|---|----|------|------|
| 1 | 暴露 axios 实例 | `src/server/request.js` | 在 `request` 对象之外加 `export { api }`,供 `useRequest` 等需要传 AbortController signal 的场景直接拿底层 axios 单例;业务代码继续推荐用 `request` |
| 2 | 新增 hook | `src/hooks/useRequest.js`(新建,~80 行) | 自定义 hook:统一 `data/error/loading/refetch/abort`;自动 abort 飞行中的请求(unmount + 切 deps + 并发覆盖三场景);已知错误统一走 `message.error`;主动 abort 静默吞掉(`CanceledError` / `ERR_CANCELED`) |
| 3 | Login demo 改写 | `src/view/Login/login.js` | 把 try/await + `console.error` 模板替换为 `useRequest({ manual: true })` + `refetch(sendData)`;按钮加 `loading` prop,登录中自动 spinner + 禁用;`api.post('login', params, { signal })` 直接挂 signal,组件卸载时取消未完成请求 |

**对应 F 组未决问题决策**

| 编号 | 问题 | 本次采用 |
|------|------|---------|
| Q1 | useRequest 是否支持缓存 | **不支持**(简单版,等真需求出现再扩) |
| Q2 | 是否改 `request.js` 接受 signal | **不改**,改为暴露 `api` 实例给 hook(职责单一) |
| Q3 | 阶段 1 是否同步加 ErrorBoundary toast | **不动**;`useRequest` 走 `message.error`,ErrorBoundary 兜未知错误,两层互不重叠 |
| Q4 | 是否跑 prettier | 新文件按 `.prettierrc` 风格写,老文件不动 |

**关键设计取舍**

1. **deps 故意只用 `options.deps`**:`run` 用 `useCallback([service])` 缓存,而调用方常传 inline arrow function 作 service → 每 render 引用都变。若把 `run` 放进 effect 的 deps 会死循环,故 ESLint `exhaustive-deps` 在这里**有意 disable**,注释解释原因。
2. **manual + refetch 路径**:点击触发的请求(Login 提交)走 `manual: true`,mount 不发请求,改由 `refetch(sendData)` 携带参数显式触发。
3. **abort 语义统一**:`refetch` 返回 `undefined` 表示"被 abort 或已 toast 的错误",调用方据此判断是否继续业务流程(见 Login `if (data === undefined) return`)。
4. **loading 清理防抖**:`finally` 里只在 `controllerRef.current === controller` 时清 loading,避免快速并发中"上一个请求的 finally 把新请求的 loading 提前清掉"。

## 2026-06-09 view 分支 G 组:dev 脚本默认只跑 React

**目的**:日常开发主要在浏览器里调 UI,无需每次都启动 Electron 主进程。把 `npm run dev` 收窄为只跑 Vite,Electron 需要时单独走 `npm run dev:electron`。

**改动范围**:1 个文件

| # | 项 | 文件 | 说明 |
|---|----|------|------|
| 1 | dev 脚本拆分 | `package.json` | `dev` 由 `concurrently "npm run react-dev" "npm run electron-dev"` 改为 `vite`;新增 `dev:electron` 保留完整 React + Electron 联动启动方式 |

**新脚本对照表**

| 命令 | 行为 | 适用场景 |
|------|------|---------|
| `npm run dev` | 只跑 Vite,端口 5175 | 日常 UI 开发(默认) |
| `npm run dev:electron` | 同时跑 Vite + Electron 主进程 | 需要测试 Electron API、菜单、IPC 等场景 |
| `npm run react-dev` | 单独跑 Vite(供 `dev:electron` 内部用,也可手动调) | 调试用 |
| `npm run electron-dev` | 等 5175 起来后启动 Electron(供 `dev:electron` 内部用) | 调试用 |

**理由**
- `concurrently` 默认会同时启两个长进程,即使只想看 UI 也得等 Electron 主窗口启动
- Electron 进程在依赖未完整安装时(本地存在 `react-rough` peer-dep 阻塞)会静默失败,容易误判 UI 问题
- 浏览器调试 React 比 Electron 内嵌 Chromium 更顺手(DevTools、React DevTools、Network 一应俱全)

## 2026-06-09 view 分支 D 组修复(3 个 bug)

**目的**:修复 3 个真实 bug——一个从未生效的渲染进程监听器、一个缺失的错误边界、一个错误的 401 跳转。

**改动范围**:5 个文件 / 新增 36 行

| # | 项 | 文件 | 改动 | 原因 |
|---|----|------|------|------|
| 1 | **`render-process-gone`/`did-fail-load` 监听器从未生效** | `electron/main.js` | 把两个监听器从文件顶层移到 `createWindow()` 内部,删顶层 `win?.webContents.on(...)` | 顶层代码在 `app.whenReady()` 触发前执行,此时 `win` 还是 `null`——可选链 `win?.` 看到 `null` 直接跳过,所以**从 v0.1.0 开始这两个监听器从未工作过**。搬到 `createWindow()` 内,`win` 已赋值,监听正常生效 |
| 2 | **缺失 ErrorBoundary** | 新增 `src/common/ErrorBoundary.jsx`、`src/index.js` | 新建 class 组件 `ErrorBoundary`,在 `createRoot().render()` 包裹 `<App />` | 22 个 React 组件 0 个错误边界——任何组件 throw 会让整个 Electron 窗口白屏,只能重启 App。新增后未捕获错误会显示在降级 UI 上,带"重试"按钮 |
| 3 | **401 跳转用了错误的方法** | `src/server/request.js`、`src/App.js` | `window.location.hash = '#/login'` → `window.dispatchEvent(new CustomEvent('auth:unauthorized'))`;App.js 新增 `<AuthBridge />` 组件监听此事件并 `navigate('/login')` | 项目用 `BrowserRouter`(v6 路径路由),`hash` 变化**不触发** React Router 跳转——URL 变了但页面不切换。`request.js` 在 React 树外没有 hook 上下文无法直接 `navigate`,用 `CustomEvent` + App.js 监听是最干净的解耦方案 |

**401 跳转流程(修复后)**
```
server 401 → axios 响应拦截器 → 删 token → 派发 'auth:unauthorized' 事件
  → App.js 的 <AuthBridge /> 监听 → navigate('/login') → 页面切换到登录页
```

**为什么是 class 组件(ErrorBoundary)**
- React 18 仍没有 `useErrorBoundary` hook(RFC 阶段)
- `static getDerivedStateFromError` + `componentDidCatch` 是当前唯一官方支持的方案
- 这是 React 官方文档明确推荐的"为了错误边界必须用 class"的少数场景之一

**风险评估**
- Bug 1:只是把监听器搬到合适位置,等价于"修复一个一直无效的代码",无负面影响
- Bug 2:新增降级 UI,正常路径完全不变;若没有错误触发,组件等于透明 wrapper
- Bug 3:旧代码"碰巧能用"(刷新页面时 hash 跳转也能进登录页,但不是 SPA 跳转);新代码走 SPA 跳转,**体验更好**

**未提交到 master**:在 `view` 分支,本地保留,待用户自行合并。
