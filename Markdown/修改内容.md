**改动范围**:2 个文件(均改)

| # | 项 | 文件 | 说明 |
|---|----|------|------|
| 1 | 搜索 + 防抖 + 自适应分页 | `src/view/News/news.js` | 加 `keyword`/`debouncedKeyword`/`isTyping` state;`useEffect + setTimeout(300ms) + cleanup` 手写防抖;list deps 加 `debouncedKeyword`;Pagination total 在搜索模式下动态估算(满页 → 下一页可点,未满 → 已到末尾);顶部 toolbar(Input + 当前搜索 Tag);Empty 文案带关键词 |
| 2 | toolbar 样式 | `src/view/News/css/news.less` | toolbar 横向 flex + 间距;搜索框宽 320px |

**防抖实现要点**

```js
useEffect(() => {
  const t = setTimeout(() => {
    setPage(1);                       // 搜索时跳第 1 页, 避免"第 5 页搜词只剩 3 页"
    setDebouncedKeyword(keyword);
  }, 300);
  return () => clearTimeout(t);       // 输入未停时持续清掉旧 timer
}, [keyword]);
```

- **React 18 自动 batch**:`setPage(1)` + `setDebouncedKeyword(...)` 同 microtask 触发,list 只重拉一次,不会 page 先变触发一次再 keyword 变触发一次
- **取消"输入中"的请求**:每次 deps 变化触发 effect → 上次 effect 的 cleanup 跑 abort → 新请求覆盖。最终服务器收到的是停止打字后那一次

**对 useRequest 的最后一组验证点**

| 验证项 | 结果 |
|------|------|
| 多 deps 同时变化(page + debouncedKeyword) | ✓ 只重拉一次(React batch) |
| 高频 deps 变化 → 取消上一个 | ✓ AbortController 在 cleanup 跑 |
| `q: undefined` 序列化时被 axios 跳过 | ✓ axios 不会把 undefined 加进 query string |

**已知限制**

- jsonplaceholder 的 `q` 参数支持有限,实际只能匹配字段精确值,**不是真正的全文搜索**。前端代码逻辑正确,接 Flask 后台时换成 `q` 真支持全文检索的接口即可。
- 搜索模式下 total 用启发式估算(满页 → +1,未满 → 真实),不知道接口总数。Flask 后台返回 `{ data: [...], total: N }` 后可改为直接读 total 字段(届时需调整 axios 响应拦截器或在 service 内适配)。

## 2026-06-09 view 分支 I 组 阶段2-B:mainpage onSelect 迁移 useRequest

**目的**:F 组阶段 2 第 2 步。mainpage 的 DirectoryTree `onSelect` 回调是触发型请求(点击节点拉详情),改用 manual hook 模式;同时演示**带数据加工**场景的迁移姿势。

**改动范围**:1 个文件

| # | 项 | 文件 | 说明 |
|---|----|------|------|
| 1 | mainpage onSelect | `src/view/Pages/mainpage.js` | 换 `request` → `api`+`useRequest`;onSelect 内 try/await 改 `await fetchListInfor({ id })` + undefined 短路;新增 `fetchListInforService` 用 `useCallback([])` 包 service 保证 hook 内 `run` 引用稳定 |

**关键设计点:service 必须用 useCallback 稳引用**

`useRequest` 内部 `run = useCallback(service, [service])`,如果调用方传 inline arrow function 作 service,**每次 render service 都是新引用 → run 也是新引用 → refetch 也是新引用**。这在 Login/Register 里无影响(它们不把 refetch 放进任何 deps),但 mainpage 的 `onSelect` 用 `useCallback([fetchListInfor])` 包裹,若 fetchListInfor 不稳,onSelect 每次重建,传给 DirectoryTree 的 props 也每次重建。

**解法**:调用方把 service 用 `useCallback([])` 包一下,这是 useRequest 抽象的隐性 contract,**应写入未来重构指南**。

**与 Login/Register 的差异**

- 不取 `loading`(树点击通常很快,不需要按钮反馈)
- 取了 `refetch` 重命名为 `fetchListInfor`,因为这个 hook 复用了两次 — `useRequest()` 调用提供 hook 句柄,`fetchListInfor(...)` 是触发
- `setDetailInfor` 保留,因为有数据加工(`data.describe || 'No description'`),hook 的 data 是原始响应

**关键设计取舍**

1. **deps 故意只用 `options.deps`**:`run` 用 `useCallback([service])` 缓存,而调用方常传 inline arrow function 作 service → 每 render 引用都变。若把 `run` 放进 effect 的 deps 会死循环,故 ESLint `exhaustive-deps` 在这里**有意 disable**,注释解释原因。
2. **manual + refetch 路径**:点击触发的请求(Login 提交)走 `manual: true`,mount 不发请求,改由 `refetch(sendData)` 携带参数显式触发。
3. **abort 语义统一**:`refetch` 返回 `undefined` 表示"被 abort 或已 toast 的错误",调用方据此判断是否继续业务流程(见 Login `if (data === undefined) return`)。

### 二、统一请求层(request.js 重写 + view 迁移)

**改动前**
- `src/server/request.js` 只是"请求准备函数",返回 `[url, options]` 元组
- 每个 view 各自 `await fetch(url, options)` + `response.json()` + 重复的错误处理

**改动后**
- `src/server/request.js` 用 axios 单例 + 拦截器封装,导出 `request.get/post/put/delete`
- 请求拦截器:从 `localStorage` 自动注入 `Authorization: Bearer <token>`
- 响应拦截器:统一返回 `data`,401 自动清 token 跳登录页,统一抛 `{code, message, url}` 错误
- 4 个 view 全部从 `PostWay` / `GetWay` / 手写 `fetch` 迁移到 `request.post(...)` / `request.get(...)`

**修改文件**
- `src/server/request.js` — 完全重写
- `src/view/Login/login.js` — `PostWay` + `fetch` → `request.post()`
- `src/view/Register/register.js` — `PostWay` + `fetch` → `request.post()`
- `src/view/Pages/mainpage.js` — `GetWay` + `fetch` → `request.get()`
- `src/view/MainView/components/indexview.js` — `PostWay` + `fetch` → `request.post()`

**收益**
- view 代码量减少 ~30%(每个请求从 3 行变 1 行)
- 401 处理从"每个 view 写一遍"变成"拦截器一处生效"
- 新增页面时不用再写 fetch 样板

### 三、错误日志(Electron IPC + 主进程写文件)

**目的**:捕获渲染进程未处理错误,写入用户数据目录,便于事后排查。

**改动**
- 新增 `src/utils/logger.js`:监听 `window.error` / `unhandledrejection`,通过 `window.electronAPI.writeErrorLog` 发送到主进程;dev 环境 fallback 到 `console.error`
- 新增 `electron/main.js` IPC 句柄 `write-error-log`:在 `app.whenReady().then()` 内部注册(与现有 `ping` 一致),将日志追加写入 `app.getPath('userData')/logs/error.log`(macOS 是 `~/Library/Application Support/electron-ant/logs/error.log`)
- 新增 `electron/preload.js` `writeErrorLog` API,经 `contextBridge` 暴露到 `window.electronAPI`
- 新增 `src/index.js` import `./utils/logger`,让监听器在应用启动时挂载
- 导出 `logger.error/warn/info` 给业务侧主动调用

**顺带修复**
- `electron/main.js` 顶层的 `win?.webContents.on('render-process-gone', ...)` / `'did-fail-load'` 在 `win` 还未赋值时已运行,监听**实际从未生效**。本次新增的 IPC 句柄都放在 `app.whenReady().then()` 内部,符合既有注册位置。`render-process-gone` / `did-fail-load` 监听暂未迁移(超出本次范围,后续单独 commit)。

**日志格式**
```
[2026-06-08T03:14:25.123Z] [UNHANDLED_REJECTION] TypeError: ...
[2026-06-08T03:14:25.456Z] [JS_ERROR] ReferenceError: ...
[2026-06-08T03:14:25.789Z] [ERROR] LoginContext: 用户名不存在
```

**修改文件**
- `src/utils/logger.js` — 新建
- `electron/main.js` — 加 `fs` import + `write-error-log` IPC 句柄
- `electron/preload.js` — 加 `writeErrorLog` 暴露
- `src/index.js` — 加 `import './utils/logger'`
- `Markdown/修改内容.md` — 本节
